Session 管理

上下文 70% 是甜蜜點。

先讓對話有名字、能回頭
1
/rename　給對話一個名字
「plugin-v2.3-release」比「Untitled」好找一百倍
2
/resume　挑一個舊對話接著做
昨天的脈絡整包回來，不用重講一次背景
3
/branch　從中間岔出一條新線
同一份脈絡試兩種做法，原本那條不會被弄髒

一個任務一條 session。任務結束就換新的，不要一路續下去。

改壞了怎麼辦

對話自己
能倒帶。

Claude Code 會在每次改檔前存一個 checkpoint。
Esc Esc 或 /rewind 挑一個點回去。

/rewind 讓你選要退回什麼
▸ 只退對話　　程式碼保留
▸ 只退檔案　　對話保留
▸ 兩個都退　　整段重來

checkpoint 只涵蓋 Claude 改的檔，
你自己手動改的不在裡面。

兩條線要對話的時候

用 @ 點名另一個 session，把問題丟過去。

// 你在 frontend 這條，需要後端先定案
@api-refactor 你那邊的 endpoint 定案了嗎？

// 訊息直接送進那條 session，它回完你再繼續
POST /v1/orders，欄位清單我寫在 docs/api.md

不用自己在兩個視窗之間複製貼上轉述。

先看數字，再決定動作

兩個很像、但差很多
/compact

壓縮，不是清空。把前面的對話摘要成一段，繼續同一個任務。

時機：同一件事還沒做完，但快撐不住了。

/clear

整個倒掉。上一個任務結束，下一件事完全無關。

時機：換題目。留著舊脈絡只會干擾判斷。

判斷法：接下來要做的事，需不需要剛剛那些脈絡？

改的是「怎麼講」

同一個答案，
可以有不同
講法。

打 /output-style 切換，
也可以自己寫一份存起來重複用。

~/.claude/output-styles/teaching.md
---
name: teaching
description: 邊做邊解釋，給學員看
---
每改一個檔案，先講一句為什麼要改。

它改的是回話風格，
不是能力，也不是權限。
