Skill 架構設計

三層結構，用原生 frontmatter 就能做到。

--- SKILL.md frontmatter ---
name: plugin-release
description: 外掛發版流程
disable-model-invocation: true　入口
context: fork
agent: releaser　　　　　　執行者
---
參考 checklist.md / steps/*.md　資料
三個角色

入口　控制誰能啟動

執行者　在哪裡跑

資料　要用才讀

這三層是獨立的，
可以只用其中一層。

第一層 · 入口
disable-model-invocation: true

只有你能打 /plugin-release，
Claude 不會自作主張跑。

危險或不可逆的流程，手動觸發才安全。

副作用：它不再佔用 skill listing 的描述額度。

第二層 · 執行者
context: fork　　agent: releaser

在獨立 subagent 裡跑，
不佔主對話。

長流程的雜訊留在 fork 裡，主對話只收結果。

第三層 · 資料

SKILL.md 只放導航，
細節引用外部檔。

SKILL.md
階段導航 · 一直在
steps/03.md
做到第三步才讀
checklist.md
驗收時才讀

這叫漸進式揭露——用不到的段落，就不要花錢載進來。

最常被問的一題
抽成獨立 Skill

會被別的流程叫到，或你想單獨用 / 觸發它。

例：「i18n 翻譯」兩個外掛都在用。

做成附屬檔

只有這個流程的某一步會讀，沒有獨立生命。

例：發版第三步的 SVN 指令清單。

判斷法：它會不會被第二個地方叫到？不會，就是附屬檔。

動手改的時候，照這個順序
1
把「事實」搬去 CLAUDE.md
專案架構、命名規範，不該擠在流程裡
2
把長範例搬去外部檔
整段程式碼、指令清單，留一行連結就好
3
SKILL.md 只留階段與判斷點
看得出「現在在哪一步、下一步讀哪個檔」
4
重跑 /skill-doctor 對照
數字有沒有真的降下來

目標：SKILL.md 掃一眼就看完，其餘都在外面。

上線、刪資料、推 production

入口鎖死

disable-model-invocation: true
只有你本人打得動。

工具限縮

allowed-tools 只開必要的幾個，不給它多餘的手。

Hook 把關

PreToolUse 攔危險指令。不靠模型自覺。

三層一起上。任何一層單獨都不夠。
