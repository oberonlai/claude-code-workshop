SECTION 06

平行任務

同一時間，開好幾條工作線。

概念

一個功能
一條工作區。

不用 stash、不用切分支。
三條各跑各的，互不打架。

git worktree add ../feat-checkout feat/checkout
先確認需求，別為了用而用

線性流水線不需要 worktree，
硬開只是多開幾個視窗。

真的有價值 ①

同時服務兩個客戶案，兩條完全獨立。

真的有價值 ②

同一個需求做三版比較，並排看哪個好。

代價：每條 worktree 都要各自 composer install / npm i。

讓工作線自己跑下去
1
/goal　設完成條件
每一輪獨立評估「達標了沒」，沒達標就繼續
2
/loop　固定間隔重跑一件事
例：每 10 分鐘看一次 CI 過了沒
3
/schedule　排定時任務
例：每週一早上整理上週的 session 紀錄

關鍵在完成條件寫得夠具體——寫不清楚，它會一直跑。

再上一層

一支腳本，
調度一整批
subagent。

審查分六個面向同時跑，
每個面向的發現再各自丟去驗證。

// 六個面向平行審，各自驗
pipeline(DIMENSIONS,
　d => agent(d.prompt),
　r => parallel(r.findings.map(verify))
)

很貴。要你明確開口才會跑，
不是日常工具。

由輕到重

Subagent

一次性的調查或驗證。最常用，先從這個開始。

Worktree

兩件事真的無關、要同時進行。

Workflow

同一件事要從十幾個角度一起打。少用。
