SECTION 06

平行任務

同一時間，開好幾條工作線。

概念

一個功能一條工作區，不用 stash、不用切分支。

// 同一個 repo，開三條各自獨立的工作區
git worktree add ../feat-checkout feat/checkout
git worktree add ../feat-invoice feat/invoice
git worktree add ../fix-cron fix/cron

// 三條各跑各的 Claude Code，互不打架
先確認需求，別為了用而用

線性流水線不需要 worktree，硬開只是多開視窗。

兩個客戶案同時跑

兩條完全獨立，互不影響。

同一需求做三版

並排比較，挑最好的那一版。

讓工作線自己跑下去

完成條件寫得夠具體，它才會自己停。

1
/goal　設完成條件
每一輪獨立評估「達標了沒」，沒達標就繼續
2
/loop　固定間隔重跑
例：每 10 分鐘看一次 CI 過了沒
3
/schedule　排定時任務
例：每週一早上整理上週的 session 紀錄
再上一層

一支腳本，調度一整批 subagent。

// 六個面向平行審，每個發現再各自丟去驗證
pipeline(DIMENSIONS,
　d => agent(d.prompt),
　r => parallel(r.findings.map(verify))
)

// 很貴。要你明確開口才會跑，不是日常工具
由輕到重

先從 subagent 開始，workflow 少用。

Subagent

一次性的調查或驗證。最常用，先從這個開始。

Worktree

兩件事真的無關、要同時進行。

Workflow

同一件事要從十幾個角度一起打。少用。
