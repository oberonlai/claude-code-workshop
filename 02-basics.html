基本觀念
與環境

CLAUDE.md、Skill、MCP、Plugin
各管什麼，設定檔又該放哪。

Claude 的知識分四層放
LAYER 1

CLAUDE.md

每次都載入的事實。要短，只放不會變的前提。

LAYER 2

Skill

用到才載入的流程與參考資料。

LAYER 3

MCP / Plugin

外部工具接入。plugin 帶的 skill 另有管道。

LAYER 4

記憶機制

跨對話留下來的東西。三個來源要分清楚。

最容易放錯的一刀
CLAUDE.md｜事實

「我叫小賴」「所有回覆用繁體中文」
——每次都要知道、而且很短。

放越多，每輪都在花錢背它。

Skill｜流程

「先幫我清查老站的文章有哪些類型」
——用到那件事才需要載入。

平常不佔 context，被叫用才進來。

判斷法：這段話每次對話都要嗎？不是，就別放 CLAUDE.md。

工具這一層有個陷阱

plugin 帶進來的 skill，
不歸 skillOverrides 管。

你在 settings.json 裡關 skill 的那組開關，對 plugin 的 skill 沒用。

要管它，走　/plugin

MCP 也一樣佔 context —— 沒在用的 server，直接從設定檔拿掉。

同一個 skill，放的位置決定它的命
~/.claude/skills/

全域。每個專案都吃得到，跟著你這台機器走。

代價：所有專案都要分攤它的描述額度。

.claude/skills/（專案內）

跟著 repo 走、可以 commit。換機器、換人接手都還在。

只有這個專案會載入，不干擾別的案子。

只有一個客戶案在用的流程，就該放專案裡。

記憶不是只有一種

CLAUDE.md

你手寫的事實。永久、可版控、每次載入。

auto memory

Claude 自己記下的東西。方便，但要偶爾回頭看它記了什麼。

/memory

手動編輯記憶內容的入口。要改、要刪就從這裡進去。

記錯的記憶比沒有記憶更貴 —— 每個月看一次。

my-plugin/
├─ CLAUDE.md　　　　專案事實：架構、規範
├─ .claude/
│　├─ settings.json　可 commit，團隊共用
│　├─ settings.local.json　個人，別進版控
│　├─ skills/　　　　這個外掛專屬流程
│　├─ agents/　　　　subagent 定義
│　└─ commands/　　　斜線指令
└─ includes/ assets/ languages/
